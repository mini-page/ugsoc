Automating Active Directory & NTFS ACL Audits with PowerShell

Author: Umang Gupta · Security Automation Engineer

When assessing enterprise Windows estates, file server permission drift remains one of the top vectors for internal privilege escalation. Administrators frequently run ad-hoc icacls commands to quickly unblock users, inadvertently breaking security inheritance or granting NT AUTHORITY\Authenticated Users write access to privileged scripts.

The Problem with Native icacls

Native tools lack transactional consistency. If an icacls /grant operation fails halfway through traversing a deep directory hierarchy due to a locked file, the folder structure is left in an inconsistent hybrid state with no rollback mechanism.

Engineering the Automated Solution

To eliminate manual risk, we built a PowerShell audit pipeline leveraging .NET's System.Security.AccessControl API directly. This provides:

  • Pre-flight validation to simulate DACL changes without modifying NTFS metadata.
  • Automatic detection of canonical ordering violations (e.g., Deny ACEs placed after Allow ACEs).
  • Transactional snapshotting of existing Access Control Entries prior to any write execution.
# Enumerate non-inherited, dangerous write permissions
Get-ChildItem -Path "C:\CorporateShares" -Directory -Recurse | ForEach-Object {
    $acl = Get-Acl $_.FullName
    $dangerousAces = $acl.Access | Where-Object {
        $_.IsInherited -eq $false -and
        ($_.FileSystemRights -match "FullControl|Modify|Write") -and
        $_.IdentityReference -match "Users|Everyone|Domain Users"
    }
    if ($dangerousAces) {
        [PSCustomObject]@{
            Path = $_.FullName
            Identities = ($dangerousAces.IdentityReference -join ", ")
            Rights = ($dangerousAces.FileSystemRights -join ", ")
        }
    }
} | Export-Csv -Path "ACL_Anomaly_Audit.csv" -NoTypeInformation

Key Security Takeaway

Never rely on visual folder properties in File Explorer. Scripted policy enforcement using continuous DACL hashing ensures that unauthorized permission creep is caught immediately during regular compliance sweeps.

Designing High-Speed Terminal User Interfaces (TUIs) for SecOps

Author: Umang Gupta · Tool Engineering Lead

In high-pressure security operations, web dashboards frequently introduce unwanted friction: authentication timeouts, bulky page reloads, and mouse navigation that pulls hands away from the keyboard. When seconds count during containment, the terminal remains the analyst's ultimate weapon.

Why Most TUIs Fail

Many terminal utilities suffer from redraw flicker, lack of keyboard shortcuts, and monolithic architectures where one slow network request freezes the entire interface. In developing tools like asllock and SnipRun, we applied strict real-time engineering rules:

  • Decoupled Worker Threads: Background I/O (network probes, disk traversal) executes in worker runspaces, passing results to the UI thread via non-blocking queues.
  • ANSI Virtual Terminal Processing: Direct ANSI escape codes avoid full console clears, updating only changed character cells for a true 60 FPS terminal experience.
  • Safety Guardrails: Destructive operations (process termination, ACL wiping) require explicit two-key confirmation combinations with timeout fallbacks.

Reverse Engineering Android APKs: SSL Pinning, Dex Analysis & Frida

Author: Umang Gupta · Mobile Security Researcher

Mobile security assessments present unique hurdles compared to standard web auditing. Modern Android applications encapsulate business logic inside Dalvik bytecode, obfuscated with ProGuard/R8, and enforce strict certificate pinning via OkHttp and Network Security Config.

Bypassing Certificate Pinning at Runtime

Rather than recompiling the APK with patched XML (which breaks integrity checks like Play Integrity / SafetyNet), runtime instrumentation with Frida intercepts the native SSL handshake in memory:

// Frida Hook for TrustManagerImpl
Java.perform(function() {
    var TrustManagerImpl = Java.use('com.android.org.conscrypt.TrustManagerImpl');
    var ArrayList = Java.use("java.util.ArrayList");

    TrustManagerImpl.verifyChain.implementation = function(untrustedChain, trustAnchorChain, host, clientAuth, ocspData, tlsSctData) {
        console.log("[+] Intercepting SSL verification for host: " + host);
        return untrustedChain; // Bypass and return raw certificate chain
    };
});
